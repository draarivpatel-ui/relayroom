          How The Engine Works

          The room core is a deterministic event log. It has no timers and no network: time only moves when a clock advances it, so the same script always produces the same log.

          Strict Ordering

          Every event takes the next sequence number, one higher than the last. Messages from all four devices interleave into a single ordered stream, and each sender keeps its own counter on top.

          Heartbeats

          Each device pings the room every three seconds. A ping is an event like any other, with its own place in the log and its own sequence number.

          Stale Eviction

          A device silent for more than ten seconds is swept out with a leave event that records how long it went quiet. It can rejoin later and starts a fresh sender sequence.

          Replay Windows

          A rejoining device asks for everything after a sequence it already holds. The engine hands back that exact window of the log, copies, in order.

          About transport: this build has no server. The engine, the log and the scheduler all run in this page, which is why the badge above says Local Simulation. When a backend exists, a WebSocket transport is the drop in replacement for the in page scheduler: it would call the same engine methods and append to the same log.

          RelayRoom was built by Aariv Patel as a hackathon pre-build. It is a simulation: every device on this page is software, no server is involved, and no data leaves the tab.
